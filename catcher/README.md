# Catcher（职喵）— 脱敏案例

> **产品**：AI 求职决策平台 — 简历 + JD → 决策卡（匹配分、四维解析、投不投建议）  
> **角色**：独立负责产品定义、全栈开发与 AI 应用落地  
> **在线产品**：https://www.zhimiaojob.com  
> **仓库状态**：源代码因产品与知识产权要求不公开

---

## 1. 背景与问题

求职者在多渠道获取岗位时，痛点往往不是「找不到」，而是：

- 信息过载，判断「值不值得投」成本高  
- 通用 Chat 问答难以沉淀偏好、历史与投递状态  
- 现有工具偏「找全 / 海投」，缺少可解释的投前决策层  

职喵切入 **投递前决策**：每日精选 + 结构化决策卡，帮助用户判断这条机会是否值得投入时间。

## 2. 本人职责

独立完成：

- 产品：竞品分析、PRD / MVP、验证与迭代  
- 前端：Vue 3 用户端 + 管理后台  
- 后端：NestJS API、数据模型、权限与任务队列  
- AI：LangGraph Agent、公司事实 RAG、版本化 Prompt、降级策略  
- 工程：Docker 部署、自动化测试、隐私与限流

## 4. 脱敏架构

```text
[ Vue 用户端 ]     [ Admin ]
        \             /
         \           /
          v         v
        [ NestJS API ]
         |    |    |
         |    |    +--> Prompt 版本库 / LLM 网关
         |    +-------> RAG（公司事实检索 + 服务端引用）
         +------------> 业务：画像 / Top-N / 决策卡 / 投递状态
                          |
                          v
                   [ FastAPI Agent ]
                   LangGraph 多图编排
                   （画像 / 分析 / 对话 / 改简历 / 质检）
```

产品主路径：

```text
登录 → 简历画像 → Top-N / 校招 / 公招
     → 决策卡（分数、优势/风险/建议、证据、RAG 引用）
     → 收藏与投递状态 → 对话调偏好 / AI 改简历
```

## 5. 关键技术难点

### 5.1 LangGraph Agent 多图编排

用多条 StateGraph 覆盖画像解析、决策卡生成、对话工具调用、简历改写、质检等场景；Nest 经 HTTP 调用 Agent，并以 Feature Flag 控制启用，避免 AI 子系统拖垮主路径。

### 5.2 RAG 防幻觉引用

公司画像/公开事实分块入库后，仅在当前公司范围内检索；决策卡上的引用由服务端按检索结果写入，模型不能自行伪造来源链接。

### 5.3 Prompt 工程与注入防护

- 业务 Prompt 版本化：激活 / 回滚 / 按任务路由模型  
- 简历、JD、公司片段以结构化数据包传入，明确为不可信资料  
- Function Calling 仅允许白名单工具，参数与权限在服务端校验  

### 5.4 可用性与降级

LLM Key 失效、超时或 Agent 不可用时，规则分 + 模板决策卡兜底，保证演示与主流程不 500。

# FinClaw — 脱敏案例

> **类型**：Agent / 工具编排类平台（私人仓库）  
> **角色**：参与平台设计与核心链路实现  
> **仓库状态**：源代码因项目保密与知识产权要求不公开

---

## 1. 背景与本人职责

面向复杂业务场景，需要把 LLM 能力落到**可编排、可观测、可降级**的 Agent 工作流，而不是单次 Prompt。

本人侧重：

- Agent 工作流拆分与工具边界设计  
- 服务端校验（工具白名单、参数校验、权限隔离）  
- 与业务 API 的集成方式（同步调用 / 异步任务 / 失败降级）  

## 2. 技术栈（公开口径）

- Python / FastAPI  
- LLM 工具调用（Tool Calling）与多步骤编排  
- 任务队列 / 异步执行（按场景）  
- 日志与链路追踪（脱敏）  

## 3. 脱敏架构

```text
[ 业务前端 / API ]
        |
        v
[ Orchestrator ]
  - 规划 / 路由
  - 工具调用提议
        |
        v
[ Tool Gateway ] ---- 白名单工具 ----> [ 业务只读/受控写接口 ]
        |
        v
[ 结果校验 + 降级策略 + 审计日志 ]
```

## 4. 关键技术难点

- **工具幻觉**：模型可能提议不存在或越权的工具调用 → 服务端白名单 + schema 校验  
- **长链路稳定性**：多步 Agent 易在中途失败 → 分步超时、重试与人工确认点  
- **数据安全**：Prompt 与日志不得泄露密钥、客户原文 → 脱敏追踪与最小必要上下文  

## 5. 成果（不泄露内部指标）

- 形成可复用的 Agent 编排与工具网关模式  
- 关键路径支持失败降级，避免「模型一挂业务全挂」  
- 为后续 MCP / Multi-Agent 扩展预留边界清晰的工具层

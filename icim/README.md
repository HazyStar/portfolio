# ICIM — 脱敏案例

> **类型**：企业级 / 工业信息化业务平台（实验室横向或协作项目，私人仓库）  
> **方向**：Java · 业务中台式后台  
> **仓库状态**：源代码因横向项目与知识产权要求不公开

---

## 1. 背景与本人职责

面向业务方的信息化系统，需要稳定的权限模型、业务单据流转与可维护的后端结构，而不是一次性脚本。

本人职责侧重（按实际参与模块）：

- 后端业务接口与领域模块拆分  
- 认证授权（登录会话 / RBAC）  
- 与前端联调、问题排查与交付文档  

## 2. 技术栈（公开口径）

- Java、Spring Boot（或同类企业级栈）  
- 关系型数据库、缓存（按部署环境）  
- 前后端分离 API  
- 权限：角色 / 菜单 / 接口级控制  

## 3. 脱敏架构

```text
[ Web / 管理端 ]
        |
        v
[ API Gateway / 应用服务 ]
  - 认证鉴权
  - 业务模块（主数据 / 单据 / 查询统计）
        |
        v
[ DB + Cache ]
```

## 4. 关键技术难点

- **权限边界**：不同角色可见数据与可操作动作不同 → RBAC + 接口鉴权  
- **业务复杂度**：单据状态机、查询性能与可维护性之间的平衡  
- **交付约束**：横向项目需文档、联调与可交接结构，不能只「本地能跑」  

## 5. 成果（不泄露客户信息）

- 交付可用的业务模块与权限体系  
- 形成可向面试官讲述的企业级后端经验（分层、鉴权、联调、排障）  
- 客户名称、内部部署细节与生产数据不公开  

## 6. 仓库状态

```text
源代码因实验室横向项目及知识产权要求不公开。
可提供：脱敏架构说明与技术文档级讲解（不含客户数据）。
```
